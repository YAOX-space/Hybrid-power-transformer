# 夜间实验报告(2026-06-10 深夜 → 06-11 晨)

## ⚠️ 最重要的发现:验证 harness 的标定泄漏 bug → 头条数字需修正

**Bug**:`validate_frt_full.m` 的 R_fault 标定没有显式设置控制模式,第一个标定键之后**继承上一场景结束时的 mode-12(SAC 在标定期间主动撑压)**。后果:故障电阻被选得比标称更深——SAC 看到的恰是"自己补偿后=目标残压"的故障(connect 判据白送),dq 面对的是更深的故障(被系统性惩罚)。**此前的头条(SAC LVRT 95.0%/全 320 90.0%;dq 16.7%/32.8%)带有此偏置,已作废。**

**发现路径**:混合模式 mode-13 的 LVRT 路径与 mode-12 理论等价,但重跑 sym3ph 只有 40%(原 81.7%);用恢复的生产权重直接重跑 mode-12 也是 40% 且与 mode-13 逐行一致 → 排除代码/权重问题 → 定位到两套 harness 的标定模式差异。

**修复**:`validate_frt_full.m` 标定函数显式 `mode=4`(一行);全部控制器在**统一口径**(标定参照=dq-legacy 支撑下残压=目标,对 SAC 偏保守)下重测全 320。

**附带发现与修复**:Simulink 对 MATLAB Function 的 codegen 缓存不可靠追踪 coder.load 的 .mat 变化(A/B 两候选曾跑出逐行相同结果)→ `build_hpt_frt_full.m` 的 HLC 加了 build-nonce 强制每次构建重新生成代码,一劳永逸。

**新头条:混合架构 88.4%,SAC 82.2%,均大幅领先 dq 27.5%(3.0×/3.2×);SAC vs MPC 79.7% 仍领先但变近。**

要点解读:
- SAC 的 sym3ph 从(泄漏口径)81.7% 回落到 40%:统一口径下标定参照是 dq 的强串联支撑,SAC 的"克制串联"策略在中深度(0.5/0.75@强网)的 LVflt 低于参照 → connect 惜败。**这不是 Vdc/限流问题(双双 100%),是支撑深度 vs 参照的定义问题**;
- 2ph 域 SAC 98.3% 一枝独秀(所有固定律/MPC 在 2ω 无功判据上溃败 0-33%)——RL 的不对称自适应优势在统一口径下依然成立;
- **mode-13 HVRT 100%** 是夜间最大惊喜;
- 方法学注:connect 判据本质上依赖标定参照。当前参照(dq 支撑下=目标)对 SAC 保守、可辩护;若改为"无控制器参照"需重标定重测(待你拍板)。
